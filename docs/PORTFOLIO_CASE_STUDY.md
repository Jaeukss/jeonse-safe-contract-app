# Portfolio Case Study

## Project

전세계약 안심진단 AI Agent

## Context

전세계약 전 확인해야 하는 자료는 실거래가, 등기부등본, 건축물대장, 표준계약서, 보증보험 안내, 법령 등으로 흩어져 있다. 이 프로젝트는 사용자가 계약 정보를 순서대로 입력하면 위험 신호와 공식 근거를 한 번에 확인할 수 있는 인앱 MVP로 설계했다.

## My Role

- MVP 요구사항 정리
- 사용자 흐름과 정보구조 설계
- 인앱 UI 구현
- 위험 진단 엔진 구현
- RAG 문서 데이터 구조 설계
- 공공데이터 API 원천 카탈로그 구성
- 제출용 백서와 데이터셋 패키지 정리
- Hugging Face Gradio Space 배포 구조 구성
- PyTorch MLP, Pandas 시세 비교, 문서 AI, RAG 검색, 조건 분기 Agent 실행 파이프라인 구성

## Product Decisions

1. **순차형 사용 흐름**  
   사용자가 파일 업로드 화면과 결과 화면을 반복해서 오가지 않도록 문서 업로드, 계약 정보, 문서 확인, 데이터 비교, 결과 리포트 순서로 정리했다.

2. **공공기관형 UI 톤**  
   국가기관 서비스에서 사용할 수 있도록 차분한 파란색 계열, 명확한 라벨, 큰 입력 영역, 높은 대비의 버튼을 사용했다.

3. **RAG 원문 복제 대신 공식 링크 보존**  
   법령과 안내문 원문 전체를 복제하지 않고 공식 URL, 요약 chunk, 위험키, 활용 목적을 분리했다. 최신성과 저작권 리스크를 낮추는 구조다.

4. **심사 환경 대응**  
   공공데이터 API는 인증키가 필요하므로 seed 데이터를 포함해 즉시 실행되게 만들고, 운영 단계에서는 수집기로 원천 데이터를 교체할 수 있게 했다.

## Core Data

- 실거래가 MVP 데이터
- 건축물대장 MVP 데이터
- RAG 근거 문서 데이터

- 공공데이터 API 카탈로그
- 전처리 원칙

## Risk Signals

- 전세가율 과다
- 시세괴리율 과다
- 근저당권
- 압류·가압류
- 신탁등기
- 임차권등기
- 최근 소유권 이전
- 위반건축물
- 다가구 선순위 보증금 미확인
- 필수 문서 미확인

## Outcome

최종 산출물은 Hugging Face Gradio Space에서 실제 모델 파이프라인이 실행되는 앱, GitHub 포트폴리오형 README, 백서, 데이터셋, 공식 출처 링크표, 검증 스크립트를 포함한다. 심사자는 앱을 실행하면서 동시에 데이터셋과 근거 문서를 확인할 수 있다.
