# LAG 체인 설계

이 프로젝트에서 LAG는 `Load · Analyze · Ground` 흐름으로 정의한다. LangGraph형 상태 분기와 RAG 근거 연결을 MVP 안에서 재현한 구조다.

## 체인 단계

1. Load: 사용자 입력과 PDF/문서 텍스트를 로드한다.
2. Analyze Market: 실거래가 seed/API 데이터에서 유사 거래를 찾고 적정 전세가·추정 매매가를 산출한다.
3. Analyze Docs: 등기부등본, 건축물대장, 확인설명서 텍스트에서 근저당권, 압류, 신탁등기, 위반건축물 신호를 추출한다.
4. Graph Score: 주택유형과 위험 신호에 따라 점수와 등급을 분기한다.
5. Ground: 위험 신호를 법령·HUG·체크리스트 근거 문서에 연결한다.
6. Generate: 위험등급, 진단 신뢰도, 위험 사유, 확인 문서, 다음 행동을 리포트로 생성한다.

## PDF 업로드 처리

브라우저 File API로 PDF/TXT/JSON/CSV 파일을 읽는다. 텍스트 기반 PDF는 PDF 내부 텍스트 연산자 일부를 추출하고, 스캔 PDF처럼 텍스트가 없는 문서는 직접 입력으로 보완한다. 고도화 단계에서는 PDF.js, OCR, LayoutLMv3를 붙인다.

## 출력 원칙

- 전세사기 여부를 단정하지 않는다.
- 확인된 정보와 미확인 정보를 구분한다.
- 데이터가 부족하면 `검토불가` 또는 `추가 확인 필요`로 표시한다.
- 다음 행동은 계약 전 사용자가 실제로 수행할 수 있는 문서 확인 단위로 제시한다.
