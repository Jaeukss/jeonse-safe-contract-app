# OCR 한계와 고도화 계획

## 현재 MVP 판단

현재 버전은 API 키 없이 동작하는 것을 우선으로 두고, PDF/TXT/이미지에서 텍스트를 추출한 뒤 규칙 기반 파서로 주소, 보증금, 월세, 면적, 층, 건축연도, 권리관계 신호를 읽는다.

핵심 포지셔닝은 OCR 완전 자동화가 아니라 **OCR이 틀리거나 실패해도 사용자가 원문을 확인하고 보정해서 진단까지 갈 수 있는 입력 안정화 워크플로우**다.

## 현재 적용한 안전장치

- PDF는 PyMuPDF, pdfplumber, pypdf 결과를 비교해 가장 긴 텍스트를 선택한다.
- pdfplumber 표 추출 결과도 함께 후보 텍스트로 사용해 표 형태 계약서와 확인설명서 대응력을 높인다.
- 스캔 PDF와 이미지는 전처리 후 Tesseract OCR을 시도한다.
- 문서 업로드 후 OCR 원문을 화면에서 확인하고 수정한 뒤 다시 분석할 수 있다.
- OCR 추출값, 사용자 입력값, 공공데이터값이 다르면 바로 덮어쓰지 않고 충돌 확인 단계로 보낸다.
- 최종 진단에는 확정된 스냅샷만 사용한다.
- `OPENROUTER_API_KEY`가 없으면 LLM 경로를 사용하지 않고, API 키를 넣었을 때 OpenRouter 기반 구조화 JSON 추출로 확장한다.

## 남아 있는 한계

- 스캔 품질이 낮거나 기울어진 문서, 작은 글씨, 흐릿한 도장은 OCR 정확도가 낮을 수 있다.
- 한국어 계약서와 등기부등본은 표, 병합 셀, 괄호, 특약 문구가 많아 단순 텍스트 추출만으로 문맥이 손실될 수 있다.
- 보증금, 월세, 층수, 주소가 표 안에 분리되어 있거나 줄바꿈이 깨지면 규칙 기반 파서가 놓칠 수 있다.
- 표준계약서 양식, 등기사항증명서, 중개대상물 확인설명서의 버전이 달라지면 키워드 규칙을 추가해야 한다.
- API 키 없이 동작하는 MVP라 LLM이 문맥을 보고 값을 보정하는 단계는 아직 비활성화되어 있다.
- 현재 진단은 법률 판단을 대체하지 않으며, 위험 신호와 확인 행동을 정리하는 보조 도구다.

## 다음 고도화 순서

1. 실제 익명화 계약서, 등기부등본, 건축물대장 샘플을 모아 OCR 실패 유형을 분류한다.
2. OCR 원문과 정답 JSON을 함께 저장해 항목별 추출 정확도 평가셋을 만든다.
3. EasyOCR, PaddleOCR, CLOVA OCR, Google Document AI 중 비용과 품질을 비교한다.
4. 개인정보 마스킹 후 OpenRouter의 `nvidia/nemotron-3-super-120b-a12b:free`를 단일 메인 모델로 사용해 주소, 보증금, 월세, 면적, 층, 권리관계 신호를 JSON 추출한다.
5. OCR 신뢰도와 LLM JSON 신뢰도를 함께 표시하고, 낮은 항목은 사용자 확인을 강제한다.
6. 표 위치 정보가 필요한 문서는 layout-aware OCR 또는 PDF table extraction을 별도 경로로 분리한다.

## 발표용 한 줄

본 MVP의 차별점은 OCR을 완벽하게 맞히는 것이 아니라, OCR 실패와 입력 충돌을 전제로 설계해 사용자가 계약 전 확인해야 할 정보를 끝까지 복구하고 진단 리포트로 고정하는 점이다.
